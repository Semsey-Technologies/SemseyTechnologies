Operational Protocol

Multi-Persona Security Protocol

Practical rules to create and operate multiple online personas safely with minimal cross-contamination.

1. Purpose & Threat Model

This protocol helps you run isolated personas to reduce the risk of identity linking, data leaks, and targeted profiling. Identify the threat model (who might try to link personas and why) before creation.

Threat Model Checklist

  • Adversary type: Web scrapers, targeted individuals, legal investigators, or employers.
  • Data sources: Social media, email headers, public records, payment records.
  • High-value identifiers: Phone number, personal email, IP addresses, biometric media.

2. Persona Creation Template

Store these templates in an encrypted password manager. Fill one for every unique identity.

Name/Handle: [e.g., Alex Rivers]
Purpose: [e.g., Tech hobbyist, X Forum]
Backstory: [Age range, non-identifying city]
Primary Contact: [Burner email or alias]
Payment/Recovery: [Prepaid card / Crypto / None]
Environment: [Profile B in Browser X on VM Y]
Network: [VPN / Tor / Bouncer]

3. Operational Golden Rules

  • Compartmentalize: Separate email, phone, and browser profiles for each persona.
  • Unique Credentials: Never reuse passwords. Generate long, random strings via manager.
  • Strip Metadata: Remove EXIF from images before uploading (or screenshot the original).
  • Network Isolation: Use separate browser containers plus a VPN. For high separation, use VMs.
  • No Cross-Posting: Never post the same phrase or personal anecdote across different personas.

Account Creation Checklist

  1. Create burner email or alias.
  2. Generate unique password in manager (e.g., "Persona-AlexRivers").
  3. Set up app-based TOTP (avoid SMS).
  4. Clear cookies before first use in a dedicated profile.
  5. Sign up from the correct network context (VPN/Tor).

4. Communications & Style

Write style determines your digital fingerprint. Decide a consistent tone for each persona (casual, formal, technical) and stick to it to avoid stylistic linking.

  • Use approximate dates (e.g., "late 2010s") instead of exact timelines.
  • Never post raw photos of yourself or current locations.
  • If a face is required, use AI-generated avatars that do not resemble you.

5. Incident Response

  1. Immediately revoke sessions and change passwords.
  2. Revoke OAuth/connected apps on the compromised account.
  3. Review public posts for sensitive info — redact if possible.
  4. Retire any linked personas if a cross-contamination occurs.
